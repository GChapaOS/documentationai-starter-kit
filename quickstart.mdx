## Overview

This quickstart helps you sign in, set up your account, and complete a first shipment workflow from start to finish. It is written as a starter kit template, so you can adapt the labels, fields, and routing rules to match your own operation.

For this example, CFC Ops is a transportation and logistics workspace with support for account access, shipment creation, quote requests, and shipment tracking. You can use the same flow to onboard a new team member or to validate your first end-to-end shipment.

<Callout kind="info">
Before you begin, make sure you have an active account, access to your company profile, and the origin and destination details for at least one shipment.
</Callout>

## Sign in and account setup

Use your company login to enter the system and review your profile settings. If your organization uses role-based access, confirm that you can create shipments and view tracking records before you proceed.

<Tabs>

  </Tab>

## Create your first shipment

A shipment record usually starts with a clear origin, a destination, a service type, and a short description of what you are moving. Keep the first version simple so you can confirm that your process works before you add advanced routing rules.

### Recommended fields

| Field | Example value | Why it matters |
|------|------|------|
| Shipment name | Norte 001 | Helps your team find the record quickly |
| Origin | Monterrey, NL | Establishes the pickup location |
| Destination | Querétaro, Qro. | Establishes the delivery location |
| Service type | Consolidated freight | Matches the handling workflow |
| Reference | PO-20418 | Links the shipment to your internal order |

<Steps>
  <Step title="Add the shipment basics" icon="package">
    Create a new shipment and enter a descriptive name that your team can recognize immediately.
  </Step>
  <Step title="Enter origin details" icon="map-pin">
    Add the pickup city, state, contact name, and any notes about access or dock restrictions.
  </Step>
  <Step title="Enter destination details" icon="flag">
    Add the delivery address, recipient, and receiving hours so the shipment can be routed correctly.
  </Step>
  <Step title="Review and save" icon="check-circle">
    Confirm the information, then save the shipment so you can request a quote.
  </Step>
</Steps>

## Request a quote

Once your shipment is saved, submit the details needed for pricing. In a real workflow, this often includes dimensions, weight, pallet count, service level, and any special handling requirements.

<CodeGroup tabs="cURL,JavaScript,Python">
  ```bash
  curl -X POST "https://api.example.com/v1/shipments/quotes" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "shipmentName": "Norte 001",
      "origin": {
        "city": "Monterrey",
        "state": "NL"
      },
      "destination": {
        "city": "Querétaro",
        "state": "Qro."
      },
      "weightKg": 840,
      "pallets": 12,
      "serviceLevel": "consolidated"
    }'
  ```

  ```javascript
  const response = await fetch("https://api.example.com/v1/shipments/quotes", {
    method: "POST",
    headers: {
      "Authorization": "Bearer YOUR_TOKEN",
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      shipmentName: "Norte 001",
      origin: { city: "Monterrey", state: "NL" },
      destination: { city: "Querétaro", state: "Qro." },
      weightKg: 840,
      pallets: 12,
      serviceLevel: "consolidated"
    })
  });

  const quote = await response.json();
  console.log(quote.totalPrice);
  ```

  ```python
  import requests

  url = "https://api.example.com/v1/shipments/quotes"
  headers = {
      "Authorization": "Bearer YOUR_TOKEN",
      "Content-Type": "application/json"
  }
  payload = {
      "shipmentName": "Norte 001",
      "origin": {"city": "Monterrey", "state": "NL"},
      "destination": {"city": "Querétaro", "state": "Qro."},
      "weightKg": 840,
      "pallets": 12,
      "serviceLevel": "consolidated"
  }

  response = requests.post(url, headers=headers, json=payload)
  print(response.json()["totalPrice"])
  ```
</CodeGroup>

After you submit the quote, review the response for transit time, service options, and any accessorial charges. If the price looks correct, continue to shipment confirmation.

## Track a shipment status

Tracking gives you visibility after pickup. In most operations, you will review milestones such as created, scheduled, in transit, and delivered. Keep your reference number handy when you search.

<Tabs>
  <Tab title="Tracking by reference" icon="search">

    ```bash
    curl "https://api.example.com/v1/trackings/NORTE-001" \
      -H "Authorization: Bearer YOUR_TOKEN"
    ```

  </Tab>
  <Tab title="Typical status flow" icon="truck">

    ```mermaid
    graph LR
        A[Created] --> B[Scheduled]
        B --> C[In Transit]
        C --> D[Delivered]
    ```

  </Tab>
</Tabs>

<Expandable title="What to do if tracking is missing" default-open="false">
  
If a shipment does not appear right away, confirm that you are using the correct reference number and that the shipment has been saved. You can also wait a few minutes if your system syncs status updates asynchronously.

</Expandable>

## Best practices

- Use one naming convention for every shipment so your team can search records quickly.
- Enter origin and destination details before you request a quote.
- Keep reference numbers consistent with your internal order system.
- Validate the quote before you confirm dispatch.
- Check tracking updates after pickup so you can respond to delays early.
